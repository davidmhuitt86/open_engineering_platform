# OEP UX Render Reference Index

**Status:** Design reference\
**Storage:** `docs/architecture/ux/renders/README.md`

## Purpose

Define the visual references used to communicate the intended OEP/EAM UX
direction. Renders are visual references and do not replace behavioral
specifications.

## Reference set

-   **DR-UX-001 --- OEP Home:** simplified Home, Continue Working,
    Recent Work, Studios, concise status.
-   **DR-UX-002 --- OEP Studio Shell:** native Studio navigation,
    non-browser Studio tabs, workspace tabs, contextual navigation.
-   **DR-UX-003 --- EAM Acquisition Workspace:** acquisition as a
    first-class workspace, workflow rail, identity, contextual
    navigation.
-   **DR-UX-004 --- Object Detail:** contextual Objects, relationship
    context, evidence, validation.
-   **DR-UX-005 --- Diagram Integration:** EAM-to-Diagram contextual
    transition and preserved work identity.
-   **DR-UX-006 --- Validation:** contextual validation, severity,
    grouped results, Locate actions.
-   **DR-UX-007 --- Repository Browser:** independent repository
    browsing/search while preserving OEP shell identity.

## Render usage rules

1.  Use renders for visual hierarchy and spatial intent.
2.  Use specifications for behavior.
3.  Do not infer backend architecture from mockups.
4.  Do not add a global destination solely because a subsystem exists.
5.  Reconcile render/spec conflicts before implementation.

## Baseline aesthetic

Dark engineering-tool aesthetic, blue primary interaction accent,
restrained status colors, compact typography, thin borders, structured
panels, high information density, and OEP-native navigation.
