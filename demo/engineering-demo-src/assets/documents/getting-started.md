# Getting Started with the Engineering Demo Package

This package exists to demonstrate the `.oep` package format (PKG-001/PKG-002) end to end, using the `oep-package` CLI (`@oep-exchange/package-cli`) built for this purpose.

## What's inside

- `manifest/package.json` — the PKG-002 manifest, generated by `oep-package create`.
- `package.info` — human-readable package metadata (PKG-001 §6).
- `fragment/objects/` — two sample Engineering Objects: a GL1200 ignition wiring harness `Component`, and the `Diagram` that documents it.
- `fragment/relationships/` — one sample Relationship (`Documents`) connecting the two objects above, so installing this package exercises both the Engineering Object and Relationship registration paths (WP-REP-001). Renamed from `repository/` to `fragment/` in WP-REP-002, per the ratified PKG-001 terminology (a package contains a Repository Fragment, not an entire Repository).
- `assets/images/cover.svg` — a cover image referenced by this package's Marketplace listing.
- `assets/documents/getting-started.md` — this file.
- `licenses/LICENSE.md` — this package's license text.
- `signatures/package.sig` — an Ed25519 signature (PKG-005) by publisher `demo-publisher`, produced by `oep-package sign` (`@oep-exchange/signing`, WP-REP-004). Covers every file above. Installing this package into a Foundation Repository that hasn't explicitly trusted `demo-publisher`'s certificate installs it as `UnknownPublisher`, not `Trusted` — see `oep_foundation`'s `oep trust` command.

## Building and signing this package

```sh
oep-package validate demo/engineering-demo-src
oep-package sign demo/engineering-demo-src --key <publisher-private-key.pem> --publisher-id demo-publisher --public-key <hex>
oep-package build demo/engineering-demo-src -o engineering-demo.oep
oep-package validate engineering-demo.oep
```

This archive is rebuilt with the ZIP "Stored" (uncompressed) entry method rather than the CLI's own DEFLATE default, so it can be installed by `oep_foundation`'s Repository Runtime (WP-REP-001), whose `ZipReader` only supports Stored entries — see `oep_foundation/platform/installer/README.md`. Signing must happen before this Stored re-pack (and before `build`), since the signature covers the archive's file contents, not its compression method.
